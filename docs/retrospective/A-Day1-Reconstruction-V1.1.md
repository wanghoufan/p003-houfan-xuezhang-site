### 2.2 用户场景补充

- **国内访客（主场景）**：用 GitHub Pages 主地址；页面 268KB HTML（线上抓取）+ 本地 WebP；头像曾慢到 1–13 秒，故内联 base64（`8874ffa`）。**推论**：作品多、页面大时，首屏与图片仍是体验瓶颈。
- **手机窄屏访客**：390×844 一列卡片；页头同时放导航、语言、主题，易拥挤；导航 12px 低于可读下限（见 A5）。
- **微信/社交分享访客**：分享卡片依赖 `metadata` + `public/og.png`（`layout.tsx` 25–59 行）；`NEXT_PUBLIC_SITE_URL` 未设时回落到一个旧 Vercel 预览地址（`layout.tsx` 21–23 行），可能导致分享域名不一致。**【推断】** 需在 Pages 构建时注入正确 `SITE_URL`（workflow 已注入 `NEXT_PUBLIC_SITE_URL`）。
- **海外/英文读者**：手动切 EN，默认中文；服务端永远中文，切换后才变；没有按系统语言自动选择。**【核实】** `LangToggle.tsx` 注释与实现。
- **只想“点开就能用”的访客**：主按钮直接外链成品；不读详情。这是卡片语义三次纠正后的真实主路径。**【推断】** 无点击埋点，无法量化。
- **站长批量加作品**：一次要改 3 个文件 + 1 张封面 + 可能 1 张图集；作品多时容易漏英文或漏计数。
- **分享单个作品的人**：可以直接发 `/projects/<slug>/` 链接（详情页存在），但站内没有入口；对访客是“能到但找不到”。
- **回访者**：主题/语言存 `localStorage`；换设备不继承；无“最近更新”排序，新作品按数组顺序（最新多在前部，见 `posture-guard` 在首位）。

在 A V1.0 的 Day 1 提示词基础上，必须再加这 7 句（每句都是本项目真实踩过的坑）：

1. **内容边界**：“站上只放我自己的作品和联系方式，不放任何第三方代充值、返利、推广外链；如果以后要放，先告诉我可能被搜索引擎判风险。”
2. **内容全集**：“我的作品清单先按这份一次盘清（可贴 GitHub 主页/表格），第一次尽量全上墙，之后只增量；页面上的作品数、分类数不要手写，跟着清单自动算。”
3. **卡片出口三选一**：“每件作品只允许三种真实出口：在线站、安装包下载页、源码仓库；没有的就不放按钮。私有仓库不许露出，只能给官网落地页或标‘内测中’。”
4. **详情页去留**：“如果卡片只放成品和源码，就明确说详情页是‘存档页、不给入口’，还是干脆不做；不要做一套没人能点到的页面。”
5. **部署与验收通道**：“主地址用哪个、备用地址用哪个、push 后多久生效、我在哪能看到构建结果；如果某条线在这台电脑打不开，提前说清怎么验。”
6. **英文与主题的维护成本**：“要英文就把作品介绍一开始按中英两份给；要几套主题一次说，新增主题需要同步改样式、首屏脚本、切换器三处。”
7. **发布前检查**：“发布前把所有外链真的点一遍；至少自动检查每个作品的仓库名/在线站是否 200，不要只检查字符串存在。”

## 五、修订后的总体判断（供主开发者收敛）

1. **真正的第一风险是“内容边界”而非技术**：第三方推广导致整域信任受损，是唯一影响所有子站的事件；但责任应落在“计划者未做合规审查 + 开发者擅自新增服务区”，不能只写成“用户没提前说”。
2. **第二风险是“作品规模与卡片语义”**：作品从 0 到 37、卡片三次纠正、详情页失去入口，构成一条完整的“展示型站点信息架构”返工链。
3. **第三风险是“部署与验收通道”**：模板错配、两次构建迁移、Vercel 本机不可达、Pages 子路径，都是“上线后怎么验”没提前定的连带成本。
4. **A 相对 B 的增量价值**：B 擅长把“内容策略/规模/外链”讲成七问；A 补上了 B 漏掉的“详情页孤儿化、双语三处维护、派生数字漂移、自动化验收边界、手机页头字号”五项可执行缺口。
5. **B 相对 A 的增量价值**：B 把 A 归入“正常迭代”的视觉方向、服务区、模板错配提升为“可提前问”的问题，并给出通俗问句与体检表；A 接受其中“可降低返工”的部分，但拒绝把“用户没说的审美”算成用户责任。

## §13 终审素材包（≤900 字）

**可预防返工 Top5（按影响排序）**

4. 卡片语义三次纠正，并连带把 37 个详情页做成无入口孤儿（`43751d3`；首页 0 条详情内链）。
5. 外链无发布前巡检：仓库改名、私有仓、平台下线、封面热链（`36cc1ee`、`7ff0ff6`、`fe3a201`、`d75657f`）。

**正常迭代**：视觉方向探索、作品持续增长、素材校准、双语后置、托管迁移；这些不能以事后知识否认当时不确定性。

**计划者应前置发现**：内容红线与合规、模板多余能力、作品全集、卡片出口、部署主备与验收通道、外链健康、详情页定位、派生数字自动化。

**UI/信息架构条件性规则**：卡片只放“成品+源码”两个出口；密度用真实尺寸量，不靠目测；筛选计数钉右侧、标签自行换行；详情页要么有入口、要么明确存档；主题/语言新增必须三处同步；手机页头别把导航与两个开关都塞满。

**Day 1 应确认**：站上放什么/不放什么；作品清单一次给全；点卡片去哪；主备地址与验收通道；要不要英文/几套主题；素材比例与版权。

**适用与反例**：适用于个人展示/作品集静态站；作品为零者可渐进补内容；单页工具站不需要筛选/详情；内部非公开站不适用搜索风控规则。

**责任划分**：用户说清内容边界、受众、参考风格与素材；计划者查模板匹配、合规、外链、部署与验证通道；开发者保证实现、量测与真实点击/外链测试，不擅自加商业化内容。
