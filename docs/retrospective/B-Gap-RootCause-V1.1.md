## 三、终审素材摘要（≤700 字）

P003 是纯静态中文优先个人站（Next.js 16 静态导出），单页叙事 + 37 件作品卡片墙 + 孤儿化详情页，双线部署 GitHub Pages（主）/Vercel（镜像），14 条自动测试。B 路对 A 报告 20 项高影响断言逐条回原始材料核查：17 项独立证实，2 项需澄清（4 件无仓作品实有落地页；两处 CSS 行号偏移），3 项维持未证实（真机目检、外链逐条可用、英文人工质量），**未发现实质性错误**。

缺口根因集中在五类，均可回溯到 Day 1 未说清的"一句人话"：
1. **出口语义未定**：卡片按钮该指向什么（成品/落地页/仓库）在 10 月下旬才因私有仓露出问题返工三次才定型；Day 1 说"每件作品给真实存在的入口，没有就不放"即可避免。
2. **详情页定位未定**：访客点卡片去哪里从未被明确决策，导致 37 个详情页建成后无人可达、README 仍在描述一条不存在的路径；这是"有详情页"默认假设与"卡片只要成果"用户纠正之间的结构性裂缝。
3. **数量无单一真值**：README 三处数字手写（35/15/8/12/34 全部漂移），测试只钉 content.ts 不钉文档；Day 1 约定"文档数字从内容文件生成"即根除。
4. **外链会腐烂无巡检**：仓改名、平台关停、Safe Browsing 整域判红（10-15 判定、10-23 处置）都是"当时真实、事后死链"；测试只钉仓名不请求外站。
5. **签收环节缺失**：三主题、双语、37 件形态均无用户签字记录，"已上线"被默认为"已认可"。

探索型变化（视觉三改、作品 0→37、托管三迁、双语后长）属真实迭代，不应记为返工。终审前剩余动作：一次只读外链巡检、一次真机三主题×两宽度目检、README 数字修正、详情页去留由用户拍板。
